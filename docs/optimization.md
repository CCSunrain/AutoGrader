# 系统待优化项清单

审视整个 AutoGrader 系统后整理的待优化项，按优先级分类。

## 高优先级（影响核心体验 / 正确性）

1. **助教（TA）角色前端区分**：后端已区分 `PUBLISH_ROLES`（ta 可复核、不可发布），但前端所有教师类角色都显示完整功能，ta 不应看到「发布」按钮。
2. **教师邀请 / 管理助教成员**：目前只有学生通过邀请码加入，缺少「教师把某人设为助教/教师」的成员管理机制（Membership 模型已支持，缺 API + 前端）。
3. **评阅台证据定位导航**：长报告中，中栏无法「跳转到某条证据位置」，只能靠滚动。应支持点击证据 → 原文滚动高亮。
4. **模型意见冲突标记** ✅：评阅 engine 对每项两次采样（低温+高温），档位不一致时标记 `model_conflict` + 待复核，前端评分项展示「模型两次判断不一致」。
5. **矛盾检测与评分项关联** ✅：矛盾检测结果按关键词（实验/数据/结论）关联到对应评分项，前端在该评分项下展示矛盾告警。

## 中优先级（体验完善）

6. **课程编辑** ✅：前端课程卡片加「编辑」。
7. **量表版本冻结的显式入口**：后端有 freeze API，前端无「冻结当前版本」按钮（目前只能靠编辑已冻结版本时隐式建新版本）。
8. **量表删除** ✅：后端 `DELETE /rubrics/{id}` + 前端「删除」。
9. **作业编辑 / 截止日期** ✅：后端 `PATCH/DELETE /assignments/{id}` + 前端「编辑/删除」。
10. **学生上传后的实时状态反馈** ✅：提交列表与评阅状态 3s 轮询，评阅台 pending 时 2s 轮询。
11. **发布后纠错新 revision 的显式入口** ✅：评阅台已发布后显示「发起修订」，一键创建新 review。
12. **待复核项批量处理**：评阅台逐项点档位，无「批量标记/批量定档」。
13. **课程邀请码管理**：教师应可查看/重置邀请码，前端目前只在课程卡片显示邀请码，无重置。

## 低优先级（工程化 / 安全 / 质量）

14. **HTTPS 自动化**：部署文档用 Caddy 手动配置，可考虑把 Caddy 集成进 docker-compose 自动签证书。
15. **数据库定时备份**：文档有手动 `pg_dump` 命令，未做定时自动化备份。
16. **单元测试补充**：端到端测试依赖真实 LLM（慢、耗 credits），缺少 mock LLM 的单元测试，CI 无法快速回归。
17. **前端测试**：前端无任何测试（组件/交互）。
18. **评估脚本准确性提升**：`evaluate.py` 单次采样，准确性受模型限制，可加多次采样 + 投票。
19. **生产 CORS 域名配置**：`cors_origins` 需在部署时按域名配置（同域 nginx 反代下其实可关闭）。
20. **日志采集 / 清理**：`RotatingFileHandler` 有轮转但无清理策略，生产可接集中式日志。
21. **Submission / Assignment 状态机**：`status` 字段（draft/submitted/graded 等）未充分利用于工作流展示。
22. **矛盾检测规则扩展**：当前只有「规模递增但耗时反向下降」一条确定性规则，可扩展（如复杂度声明 vs 代码/数据的更多校验）。
